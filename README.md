# ДОЛЬЧЕ — учебное бронирование столиков

Статический сайт на HTML, CSS и ванильном JavaScript. Без React, npm-зависимостей и сборки. Молочно-оливковое оформление, схема зала и равнозначный список, мобильная версия.

## Запуск

Откройте `index.html` либо запустите `python3 -m http.server 8000` в каталоге и перейдите на http://localhost:8000. Для стабильного localStorage рекомендуется HTTP: поведение хранения при `file://` зависит от браузера.

## Правила демо

- 8 столиков, №2 и №6 изначально заняты и не входят в пользовательские брони.
- Фильтр вместимости показывает столики с числом мест не меньше выбранного, тариф — точное совпадение. Фильтры действуют одновременно на схему и список.
- Гости: от 1 до вместимости столика. Длительность: 1–6 часов. Стоимость = тариф за столик × часы, количество гостей цену не меняет.
- После подтверждения столик занят **до отмены**, время автоматически его не освобождает. Бронь появляется в «Мои брони», повторное подтверждение не создаёт дубликат.
- Сброс требует подтверждения в диалоге; Escape или «Оставить брони» отменяет сброс.
- Учебный режим: нет оплаты, сервера и отправки данных ресторану.

## Сохранение и доступность

Ключ localStorage: `dolce-reservations-v1`, версия схемы 1. Данные проверяются при чтении: структура, уникальность столиков, вместимость и длительность. Повреждённые данные и ошибки чтения/записи показывают заметное предупреждение; интерфейс продолжает работать в памяти вкладки. После перезагрузки несохранённые изменения могут пропасть. Сброс пытается восстановить хранение; чужие ключи не удаляются.

Изменения синхронизируются между вкладками через событие `storage`, перед изменениями данные перечитываются. Подтверждения сериализуются через Web Locks API в поддерживающих его браузерах. Без Web Locks защита от дублей работает внутри вкладки, но одновременная запись из разных вкладок может перезаписать изменения. Это локальное учебное демо, не система бронирования для нескольких пользователей.

Все действия доступны с Tab / Shift+Tab, кнопки — Enter / пробел, select — стрелками. Есть видимый фокус, ссылка перехода к бронированию, текстовые статусы, live region для результатов, нативный модальный диалог. Занятые столики недоступны для выбора. Внешних шрифтов, изображений и CDN нет.

## Файлы

- `index.html` — разметка и форма.
- `style.css` — оформление и мобильные брейкпоинты.
- `app.js` — столики, фильтры, расчёт, брони и хранение.

## Проверка сценариев

1. В чистом браузере видны 8 столиков, 2 заняты, 6 доступны.
2. Проверьте вместимость и тариф вместе, включая отсутствие результатов.
3. Выберите столик на схеме и в списке; состояние выбора совпадает. Проверьте гостей и 1–6 часов, стоимость.
4. Подтвердите, повторите отправку: одна бронь, столик недоступен. Перезагрузите страницу — бронь сохранена.
5. Отмените бронь — столик снова доступен; перезагрузите.
6. Отклоните сброс кнопкой и Escape, затем подтвердите — восстановлены два занятых столика.
7. Проверьте повреждённый JSON, неверные значения, запрещённый localStorage и переполнение: видимое предупреждение, действия продолжаются в памяти.
8. Проверьте клавиатуру, диалог, ширину 375 px и синхронизацию двух вкладок.

## GitHub Pages

Адрес: https://nataliees.github.io/interactive_map/

В Settings → Pages источник **GitHub Actions**. `.github/workflows/deploy.yml` при push в `main` (или ручном запуске) копирует только `index.html`, `style.css`, `app.js` в артефакт `_site` и публикует его. Установка пакетов и сборка не нужны. Относительные пути поддерживают размещение в `/interactive_map/`.

Проверено в Chromium: начальное состояние, совместные фильтры и пустая выдача, выбор с клавиатуры и сохранение фокуса, ограничение гостей, расчёт цены, повторная отправка формы, перезагрузка, отмена и синхронизация двух вкладок, сброс/отказ/Escape, повреждённый JSON и неверные данные, ошибки чтения и записи localStorage. На ширине 375 px горизонтального переполнения нет; проверены мобильный и настольный вид. Ошибок JavaScript в этих сценариях не обнаружено.
